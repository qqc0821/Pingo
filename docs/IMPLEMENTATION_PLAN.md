# Pingo 桌面宠物执行计划

## 目标与范围

用 Electron + React + TypeScript 做出一个仅面向 macOS 的 MVP。它能够常驻桌面、展开聊天，并在用户授权后读取指定项目中的文件。

MVP 暂时不做：跨平台适配、语音、长期记忆、自动修改代码、任意 Shell 命令、插件市场、云端账号。

预计用时：业余开发约 2～3 周，集中开发约 7～10 天。

## 完成路线

```text
项目骨架
  ↓
桌面宠物窗口
  ↓
聊天界面
  ↓
模型接入
  ↓
只读本地工具
  ↓
安全与体验
  ↓
打包 MVP
```

每个阶段都应达到验收标准后再继续，避免同时调试窗口、AI 和本地工具。

## 阶段 0：准备项目（0.5 天）

### 任务

- [ ] 确认第一版只支持 macOS。
- [ ] 安装 Node.js LTS，确定使用 npm。
- [ ] 用 Electron Forge 或等价模板创建 Electron + Vite + React + TypeScript 项目。
- [ ] 建立 `main`、`preload`、`renderer` 三层目录。
- [ ] 开启 TypeScript 严格模式、ESLint 和格式化检查。
- [ ] 增加 `.env.example` 和 `.gitignore`，确保 API Key 不入库。
- [ ] 配置 `npm run dev`、`npm run build`、`npm run lint`。

### 产出

- 应用能通过一条命令启动。
- Electron 窗口内能显示 React 页面。
- 主进程和渲染进程没有启动错误。

### 验收

```text
npm run dev     # 能看到窗口
npm run lint    # 无错误
npm run build   # 能构建
```

## 阶段 1：完成宠物外壳（1～2 天）

### 任务

- [ ] 创建无边框、透明、始终置顶的宠物窗口。
- [ ] 设置合理的初始尺寸和右下角初始位置。
- [ ] 实现拖动宠物移动窗口。
- [ ] 实现屏幕边缘吸附，并避免窗口跑出可视区域。
- [ ] 加入待机、思考、成功、错误四种状态；先用静态图片或简单帧动画。
- [ ] 点击宠物展开或收起对话面板。
- [ ] 加入系统托盘菜单：显示、隐藏、设置、退出。
- [ ] 保存并恢复上次窗口位置。

### 建议文件

```text
src/main/window.ts
src/main/tray.ts
src/main/store.ts
src/preload/index.ts
src/renderer/pet/
```

### 验收

- 宠物可拖动、吸边、隐藏和恢复。
- 重启后位置仍然保留。
- 透明区域没有明显黑底或白边。
- 展开对话面板时可以正常输入，收起后不妨碍使用桌面。

### 阶段检查点

完成后先打一个 Git 标签或提交，例如：`milestone/pet-shell`。

## 阶段 2：完成本地聊天界面（1 天）

本阶段先用假数据，不连接模型。

### 任务

- [ ] 实现消息列表、输入框、发送按钮和加载状态。
- [ ] 支持 Enter 发送、Shift + Enter 换行。
- [ ] 为用户、助手、错误消息设计不同样式。
- [ ] 用定时器模拟逐字输出。
- [ ] 将宠物状态和聊天状态联动。
- [ ] 只保留最近 20～50 条本地消息。
- [ ] 增加清空会话按钮。

### 建议状态模型

```ts
type PetState = "idle" | "thinking" | "success" | "error";
type ChatStatus = "ready" | "streaming" | "failed";
```

### 验收

- 连续发送多条消息时界面不跳动、不重复。
- 输出期间有停止按钮或禁止重复提交。
- 长文本可以滚动，窗口不会被内容无限撑大。

## 阶段 3：接入模型 API（1～2 天）

### 任务

- [ ] 选择一个支持流式输出和 Tool Calling 的模型服务。
- [ ] 所有模型请求都从 Electron 主进程发出。
- [ ] 通过 preload 暴露最小 IPC 接口，渲染进程不直接持有密钥。
- [ ] 实现流式消息事件：开始、增量、完成、错误、取消。
- [ ] 加入请求超时、取消和基础重试。
- [ ] 控制发送给模型的历史消息数量。
- [ ] 将 API Key 存入系统安全存储；练习阶段可先从本机环境变量读取。
- [ ] 对缺少密钥、网络错误、额度不足给出可理解的提示。

### IPC 边界示例

```text
renderer: chat.send(message)
main:     调用模型并解析流
renderer: chat.onChunk(chunk)
renderer: chat.onDone()
renderer: chat.cancel()
```

不要向页面暴露通用的 `ipcRenderer.send`、文件系统对象或 Node.js 执行能力。

### 验收

- 用户能得到真实且流式显示的模型回答。
- 点击停止后，请求和 UI 都能结束。
- API Key 不出现在前端打包文件、日志或 Git 中。
- 模型服务不可用时，应用不会崩溃。

### 阶段检查点

完成后提交：`milestone/ai-chat`。

## 阶段 4：加入只读本地工具（2～3 天）

这一阶段最重要的是权限边界，先不要实现文件修改和任意命令。

### 任务

- [ ] 通过系统目录选择器让用户授权一个项目目录。
- [ ] 保存授权目录的真实路径，并在 UI 中始终显示当前项目。
- [ ] 实现 `list_files`：列出授权目录内的文件。
- [ ] 实现 `search_files`：搜索文件名或文本。
- [ ] 实现 `read_file`：读取指定文本文件的有限片段。
- [ ] 为三个工具定义固定 JSON 参数结构并做运行时校验。
- [ ] 实现模型工具调用循环：模型请求 → 校验 → 执行 → 返回结果 → 模型回答。
- [ ] 拒绝所有越过授权目录的路径，包括 `..` 和符号链接绕过。
- [ ] 限制单个文件大小、返回行数和工具循环次数。
- [ ] 在聊天中展示“正在读取哪个文件”，让行为对用户可见。

### 工具执行原则

- 模型只能提出请求，程序决定是否允许执行。
- 工具只接受结构化参数，不接受模型生成的 Shell 字符串。
- 项目内文本也可能包含恶意提示，不能因此扩大工具权限。
- 二进制文件、密钥文件和常见敏感目录默认拒绝读取。

### 建议文件

```text
src/main/tools/registry.ts
src/main/tools/listFiles.ts
src/main/tools/searchFiles.ts
src/main/tools/readFile.ts
src/main/security/pathGuard.ts
src/main/ai/toolLoop.ts
```

### 验收场景

- 询问“这个项目用了什么框架”，宠物能读取 `package.json` 并回答。
- 询问“入口文件在哪里”，宠物能搜索并解释。
- 请求读取授权目录外的文件时会被拒绝。
- 超大文件、二进制文件和敏感文件会被拒绝或截断。
- 连续工具调用不会无限循环。

### 阶段检查点

完成后提交：`milestone/read-only-agent`。此时 MVP 的核心闭环已经完成。

## 阶段 5：安全和使用体验（1～2 天）

### 任务

- [ ] 确认 `contextIsolation: true`、`nodeIntegration: false`、sandbox 可用时开启。
- [ ] 为所有 IPC 调用校验来源、参数和返回值。
- [ ] 删除日志中的密钥、完整 Prompt 和敏感文件内容。
- [ ] 增加模型调用超时、工具超时和统一错误边界。
- [ ] 增加设置页：模型、密钥、宠物大小、透明度、开机启动。
- [ ] 增加全局快捷键，用于呼出或隐藏宠物。
- [ ] 优化点击穿透：收起时只让透明区域穿透，展开时恢复交互。
- [ ] 处理多显示器、屏幕缩放和显示器断开后的窗口位置。
- [ ] 完成深色模式和基础无障碍标签。

### 验收

- 应用重启、断网、切换屏幕和模型报错时都不会卡死。
- 页面不能直接访问 Node.js、文件系统或任意 IPC 通道。
- 用户能随时看见当前授权项目并撤销授权。

## 阶段 6：测试与打包（1 天）

### 自动检查

- [ ] 为路径保护、参数校验和工具注册写单元测试。
- [ ] 为主进程与 renderer 的关键 IPC 写集成测试。
- [ ] 对聊天主流程做一次端到端测试。
- [ ] 运行 lint、类型检查、测试和生产构建。

### 手工回归

- [ ] 首次启动，没有 API Key。
- [ ] 正常聊天、停止生成、清空会话。
- [ ] 选择项目并读取文件。
- [ ] 尝试越权路径和敏感文件。
- [ ] 断网、API 失败和超时。
- [ ] 拖动、吸边、切换显示器、重启恢复。
- [ ] 托盘退出与快捷键显示/隐藏。

### 打包

- [ ] 生成 macOS 安装包。
- [ ] 在一台干净环境或新用户账户中安装测试。
- [ ] 记录未签名应用的启动方式；公开分发前再处理签名和公证。
- [ ] 编写最短使用说明：安装、配置密钥、选择项目、退出。

### 最终验收

用户能够完成下面的完整流程：

> 安装应用 → 看见宠物 → 打开聊天 → 配置模型 → 选择项目 → 提问 → 宠物安全读取文件 → 返回答案 → 退出并恢复状态

## 升级阶段 7：动画宠物素材与交互

本阶段只升级宠物的素材呈现与交互反馈，不扩大本地工具权限。

### 素材交付清单

- [ ] 优先提供透明 PNG 序列帧或 Sprite Sheet；只有一张透明 PNG 时先实现基础缩放、呼吸、跳动和摇摆动效。
- [ ] 单帧统一使用 256×256 或 512×512，所有状态保持相同画布、角色中心和脚底锚点。
- [ ] 像素素材不使用模糊、抗锯齿或有损压缩。
- [ ] 每组动画注明单帧尺寸、帧率、是否循环；循环动作建议 8～12 FPS。
- [ ] 素材状态包括：`idle`、`hover`、`thinking`、`working`、`listening`、`needs-action`、`success`、`error`。
- [ ] `idle`、`thinking`、`working`、`listening` 可以循环；`success`、`error`、`needs-action` 播放一次后进入对应静态状态或返回待机。

### 宠物交互

- [ ] 鼠标悬停时宠物响应鼠标，并显示语音、收起等快捷控制。
- [ ] 单击宠物展开或收起对话/任务卡；拖动超过阈值后只移动窗口，不触发单击。
- [ ] 松开拖动后继续使用现有的屏幕边缘吸附和位置保护。
- [ ] 右键提供新对话、任务记录、设置和退出菜单。
- [ ] `Esc` 依次取消语音、关闭卡片或收起面板。
- [ ] 收起态仅宠物和快捷控制接收鼠标，其他透明区域点击穿透到桌面。

### 状态联动

- [ ] `idle` 对应无活动任务；`listening` 对应正在收音；`thinking` 对应等待模型；`working` 对应工具执行。
- [ ] `needs-action` 只在权限或用户选择等待期间出现。
- [ ] `success` 和 `error` 各播放一次短反馈，然后回到待机或保留待处理卡片。
- [ ] 动画状态以真实任务事件为准，不使用与任务进度无关的随机状态切换。

### 悬浮任务卡

- [ ] 默认显示任务标题、当前阶段和状态，点击后展开详情。
- [ ] 运行中支持取消；失败支持重试和查看原因；成功支持打开结果和继续追问。
- [ ] 权限请求直接提供允许一次、始终允许和拒绝操作。
- [ ] 多任务以堆叠卡片呈现，可切换当前任务，不同时展开多个完整面板。
- [ ] 卡片出现和更新不抢键盘焦点；完成后自动收起，悬停时暂停倒计时。

### 语音与主动提醒

- [ ] 单击语音按钮开始或结束，`Esc` 取消；监听期间持续显示明确状态。
- [ ] 未经用户明确开启时不持续监听。
- [ ] 只在任务完成、失败或等待确认时主动出现；全屏或安静模式下延后非关键提醒。
- [ ] 同一错误不重复提醒，并支持暂停提醒。

### 验收

- 宠物动作与聊天、模型、工具和权限状态始终一致。
- 点击、拖动、悬停和透明区域穿透互不冲突。
- 状态切换无明显跳帧，成功和失败动作不会无限循环。
- 任务卡不抢焦点，收起状态不妨碍正常使用桌面。
- 开启减少动态效果后，所有关键状态仍能通过文字或静态变化识别。

## MVP 之后再做

按价值和风险排序：

1. 文件修改：先展示 diff，再由用户确认写入。
2. 受限命令：使用命令与参数白名单，不开放通用 Shell。
3. Git 集成：展示 diff、状态和提交历史。
4. 对话压缩与长期记忆。
5. 在序列帧交互版本稳定后，再评估 Rive 或 Live2D。
6. Windows 适配、自动更新、签名和正式发布。

## 每日开发模板

每次开发只选一个可验收的小目标：

```markdown
今天的目标：实现窗口拖动与位置保存

- [ ] 写实现
- [ ] 手工测试主场景
- [ ] 测试一个异常场景
- [ ] 更新文档或注释
- [ ] 提交代码

完成标准：重启应用后，宠物仍出现在上次位置，且不会跑出屏幕。
```

如果一个任务一天内无法完成，应继续拆分；如果某阶段的验收没有通过，不要提前叠加下一阶段功能。
