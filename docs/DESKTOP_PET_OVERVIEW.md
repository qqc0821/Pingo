# Codex 风格桌面宠物：简要实现说明

> 配套执行清单见：[IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md)。

## 1. 想做成什么

这是一个常驻桌面的小型 AI 助手：平时以宠物形象待在屏幕边缘，点击后可以聊天，也可以在用户确认后读取指定项目、运行命令或完成简单任务。

第一版不要追求“完整复刻 Codex”，只做下面这条闭环：

> 点击宠物 → 输入问题 → AI 回复 → 必要时申请执行一个本地工具 → 显示结果

## 2. 推荐技术栈

- 桌面外壳：**Electron + React + TypeScript**
- UI：React + CSS/SCSS
- 宠物动画：先用 GIF、WebP 或帧动画，后续可换 Live2D / Rive
- AI：任意支持 Tool Calling 的模型 API
- 本地数据：先用 JSON 文件，功能变多后再换 SQLite
- 打包：Electron Forge 或 electron-builder

Electron 对练手最友好：窗口、托盘、快捷键、文件系统和 Node.js 能力都有成熟方案。它的缺点是包体和内存较大；如果以后特别在意体积，可以再迁移到 Tauri。

## 3. 基本架构

```text
┌──────────────────────────┐
│ React 界面                │
│ 宠物 / 对话框 / 权限确认   │
└─────────────┬────────────┘
              │ IPC
┌─────────────▼────────────┐
│ Electron 主进程           │
│ 窗口 / 托盘 / 快捷键       │
│ AI 请求 / 工具调度 / 权限   │
└───────┬──────────┬───────┘
        │          │
   模型 API     本地受限工具
               读文件 / 搜索 / 运行命令
```

React 渲染进程只负责显示，不直接获得完整的 Node.js 权限。文件读取、命令执行和密钥保存都放在 Electron 主进程，通过白名单 IPC 接口调用。

## 4. MVP 功能

### 桌面宠物

- 无边框、透明、始终置顶的小窗口
- 鼠标拖动和屏幕边缘吸附
- 待机、思考、开心、出错四种状态动画
- 点击展开对话气泡，右键显示退出和设置
- 系统托盘入口

### AI 对话

- 输入文字并流式显示回复
- 保留最近若干轮对话
- 根据宠物状态切换动画
- API Key 放在系统安全存储中，不写进前端代码或 Git

### 简单工具

第一版只开放三个工具：

1. `read_file`：读取用户已经选择的目录内的文件；
2. `search_files`：在该目录中搜索文件名或文本；
3. `run_command`：运行少量白名单命令。

模型只能提出工具调用，真正执行前由主进程校验路径、参数和权限。修改文件、安装软件、删除内容等操作必须再次让用户确认。

## 6. 一次交互如何运行

1. 用户点击宠物并输入“帮我看看这个项目用了什么框架”。
2. UI 把消息通过 IPC 发给主进程。
3. 主进程把消息和可用工具描述发给模型。
4. 模型请求 `search_files` 或 `read_file`。
5. 主进程检查目标是否在用户授权的项目目录内，然后执行。
6. 工具结果再次交给模型，模型生成最终回答。
7. UI 流式显示回答，宠物从“思考”切回“待机”。

## 7. 开发顺序

### 第 1 阶段：宠物外壳

先实现透明窗口、拖动、置顶、托盘和状态动画。此时不用接 AI。

### 第 2 阶段：对话

加入对话气泡、模型 API、流式输出和本地历史记录。

### 第 3 阶段：工具调用

加入项目目录授权、只读文件工具和操作确认弹窗。最后再考虑命令执行与文件修改。

### 第 4 阶段：体验完善

增加全局快捷键、开机启动、通知、换皮肤、更多动画和安装包。

## 8. 最容易踩的坑

- **透明窗口**：不同系统对阴影、圆角、缩放和鼠标穿透的表现不同，需要分别测试。
- **点击穿透**：宠物透明区域可以穿透鼠标，但展开对话框后必须恢复交互。
- **安全边界**：不要把 `nodeIntegration` 直接开放给页面，也不要让模型任意拼接 Shell 命令。
- **提示注入**：项目文件中的文字不能被当成系统指令；本地工具权限必须由程序控制，而不是由模型决定。
- **上下文成本**：只把必要文件片段交给模型，不要每次发送整个项目。
- **平台差异**：先只支持自己正在使用的系统，跑通后再适配 Windows 和 macOS。

## 9. 完成标准

当下面几个场景都能稳定工作，第一版就算完成：

- 宠物可以常驻、拖动、隐藏和退出；
- 点击后能进行连续对话；
- 能读取用户选定项目中的一个文件并回答问题；
- 每次敏感操作都有清楚的确认提示；
- 重新启动后能恢复基础设置和少量历史记录。

先把它做成一个“会聊天、会安全读文件的桌面宠物”，再逐步增加写代码和执行任务的能力，练习价值已经很完整。
